# Environmental observations and site risk

## Audit of the previous flow

The pre-migration audit covered `shared/types.ts`, `shared/policy.ts`, portable inference in `shared/model.ts`, `server/engine.ts`, all integration adapters, routes and polling in `server/index.ts`, `SiteMap.tsx`, the since-removed `useWeatherAtlas.ts` and sampled weather field, plant/cohort metadata, and the data/training/model documentation.

Previously, the original fifty sites used bundled replay forecasts or Open-Meteo Previous Runs fixed 48-hour GFS features. HeatCast corrected NOAA heat index; GroundCast predicted surface moisture using frozen preprocessing/weights. The other 235 plants used NWS point/hourly or marine grid heat/wind screening. Policy selected peak forecast upper quantiles, coarse wind/rain screens, official alerts and crew evidence, then took maximum severity. Crew reports and replay lightning could force index 10. Policy already preserved task-specific holds and lightning timers.

The map received decisions for risk beacons but independently requested fifty state sample locations and arbitrary point weather from Open-Meteo. Atlas weather never entered engine scoring. Jev classified report text and suggested tasks after persistence; manual confirmation controlled those suggestions. It supplied no environmental measurements. The historical training splits, held-out sites and threshold fitting are independent of live environmental collection.

## Current flow

`Site → batched collection → normalization → enrichment → seven continuous scores → composite risk + independent task policy → SiteRiskSnapshot → /api/risk/atlas → supervisor map`

`shared/risk.ts` defines `SiteObservationV1`, its Zod validator, hazard scores, safety overrides and the versioned site snapshot. Every one of the 285 plants receives the same shape. Unknown numerical/boolean inputs are null. `validAt` and `fetchedAt` are also null when no environmental provider reading exists. Zero means an actual provider estimate of zero; local `crewReports24h: 0` means no matching reports in this application's records, not no wildlife on site. Soil and weather are model estimates, not field instruments.

Open-Meteo serves both the atlas compatibility adapter and operational collector through `open-meteo.ts`, sharing a fifteen-minute bounded cache and duplicate-batch work. Requests include temperature, apparent temperature, humidity, wind/gusts, code, hourly precipitation, CAPE and 0-1 cm/9-27 cm soil moisture. Seven days of hourly history support exact completed-hour 1/24/168-hour totals. The compatibility weather response's current 15-minute rain rate is never substituted for an hourly accumulation. A missing hour makes that rolling total null. Apparent temperature is retained separately from calculated NOAA heat index.

The dispatcher starts one ten-coordinate batch at a time, attempts each site every fifteen minutes, and records failures with a retry delay. Canonical atlas requests read persisted evidence without provider HTTP calls. Only compatibility weather routes retain the fifty-sample overview and arbitrary-point behavior. Open-Meteo cache capacity is 1,000 coordinates. Persistent provider records are kept outside public assets. Operational readings expire after one hour from fetch and two hours from valid time; explicit stale responses are immediately unusable. A fresh NWS forecast can fill missing same-hour heat/wind fields with field-level provenance. Both cohorts can use that fallback. It never substitutes a future peak for current conditions.

NWS alerts enrich every site's record. Only a successful check within ten minutes establishes absent flood/fire-weather alerts. Unexpired positive alerts still apply after a failed check. A fire-weather alert does not establish a nearby active wildfire; curated river screening does not establish floodplain membership. Simulated/historical strikes never enter live snapshots. Live positive events can trigger the ten-mile/thirty-minute rule without pretending that a complete detector feed is configured. No configured detector means strike counts remain null even when an isolated event is present. Crew evidence stays in the override list; resolving a report clears only its own hold. Jev cannot change environmental values or clear overrides.

## Scoring and coverage

Numerical scoring is now `continuous-risk-5`, with task policy `continuous-policy-5` (learned HazardCast evidence and extreme-score holds; see [guardrails](risk-scoring.md#learned-hazards-and-guardrails)). All seven channels, dominant-plus-compounding aggregation, source confidence, structured drivers and semantic crew scoring are documented in [continuous hazard scoring](risk-scoring.md). Replay and forecast-period outputs use those same pure functions; stored historical briefings keep their original values and version.

Field coverage counts 17 primary inputs: temperature, humidity, wind, gusts, 1h/24h/7d rain, weather code, CAPE, surface/root soil moisture, detected-strike count, gauge percentile, flood-alert status, nearby fire distance, red-flag status and relevant public sighting count. Coverage is `available / expected × 100` and is independent of the numerical score. A measured/model-estimated zero is available; null is missing. Missing values never contribute zero. Additional ML predictions and crew scoring factors do not inflate observation coverage; normalized provider forecast inputs do count when available. Confidence includes available factor weights and source completeness. A low partial score is not site clearance.

## Compatibility and remaining work

`GET /api/snapshot` adds `siteRisks`; `GET /api/sites/risks` returns that map and `GET /api/sites/:id/risk` returns one snapshot (404 for unknown IDs). Reads return available/unknown evidence immediately and do not fan out provider requests. The existing site refresh also prioritizes environmental collection. Real-clock `decisions` project canonical index/tasks into the existing UI contract.

Demo `decisions` and next-day briefings retain their forecast/replay periods but use the same continuous channel functions and dominant-plus-compounding aggregation. They are period-specific compatibility outputs, not the live canonical snapshot. `siteRisks` always uses system time and live evidence, even when `Snapshot.now` is a replay clock. API clients must use `generatedAt`/observation provenance for live data. Existing weather, screening, report and SSE routes remain available. The supervisor atlas now reads these same snapshots through `/api/risk/atlas?hour=0..72`, including coverage, confidence, task controls and backend forecast frames. Period-specific immutable briefings remain separate.

Frozen models, chronology, feature order, training-only preprocessing, historical exports and browser candidates are unchanged. `mlCoverage` reports availability by the original cohort; absence never bypasses environmental scoring. Frozen live model forecasts now contribute labeled heat/soil factors over their explicit valid periods; current conditions are not passed into a fixed-lead model.

Implemented source adapters and their limits are documented in [environmental providers](environment-providers.md). Still needed: licensed live strike coverage with detector health/completeness; verified hydrologic site/gauge connectivity; FIRMS authenticated area-query deployment validation if using a MAP_KEY; regional wildlife relevance review; regional soil calibration and reviewed scoring thresholds; and provider quota sizing for deployment. A process must remain running for collection. The free Open-Meteo service counts coordinate/variable usage toward quotas even when HTTP is batched. Honor [provider usage terms](https://open-meteo.com/en/terms) and [variable documentation](https://open-meteo.com/en/docs).

No new secrets are needed for the implemented free Open-Meteo or NWS paths. Jev continues to require server-side `TYPESAFE_API_KEY` with optional `JEV_MODEL`. The optional NASA FIRMS area-query path requires a server-side [MAP_KEY](https://firms.modaps.eosdis.nasa.gov/content/academy/data_api/firms_api_use.html). A future commercial lightning service needs its vendor credentials; none is chosen. USGS public gauge access supports unauthenticated limits; an optional [api.data.gov key](https://api.waterdata.usgs.gov/signup/) enables higher limits and should be provisioned for national polling. Commercial Open-Meteo service may require a server-side subscription key and customer endpoint. Never place any of these credentials in public assets.

Provider records now merge USGS stages/trends/relative baselines, FEMA exposure, conditional FIRMS detections and public wildlife context before scoring. Official alerts remain separate policy/evidence inputs; their cache and refresh path is shared across the engine and provider dispatcher.

The atlas frame contract is defined in `shared/atlas.ts`. Current frames reuse canonical snapshots. Projected observations set provenance mode to `forecast`, while source metadata retains its own mode, actual fetch time and expiry. The engine checks source freshness at actual request time and evaluates warning/hold expiry at the requested frame time. Never-collected source timestamps and unknown warning-fetch times remain null. See [frame and layer mappings](api.md#authoritative-supervisor-atlas).
