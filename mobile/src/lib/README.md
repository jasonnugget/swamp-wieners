# Device services

`api.ts` selects an editable local API origin, bounds requests and validates compact crew responses. `photos.ts` requests the native camera/library UI, normalizes photos to size-bounded JPEGs and copies drafts into the app sandbox. `storage.ts` remembers crew defaults, the last workspace and one unshared draft. `report-input.ts` validates the pure report payload and keeps its retry UUID stable when details are unchanged. Notes are optional; a blank note uses only the selected hazard type and “photo report” as its description. Nonempty notes still require 5–2,000 characters. Do not persist credentials in EXPO_PUBLIC variables or claim cached data is fresh.

`workspace-sync.ts` owns request coalescing, user-only refresh indicators, disposed-request guards and structural sharing for unchanged workspace data. Server `now` ticks alone do not replace the visible workspace; refreshed clock mode and report timestamps remain authoritative. Connection success/failure is tracked separately so identical data can become fresh or stale without changing its map identity.

`site-hazards.ts` selects today’s hazards and crew reports using the plant’s IANA timezone and real current time. It distinguishes restrictions from numeric screening, preserves zero scores, labels forecast/model/static/crew evidence, and makes scores unknown for cached, future, wrong-site or older-than-two-minute snapshots. Last-known holds remain visible until refreshed. Current-condition timestamps propagate through reconciliation while unchanged map/report arrays retain their references.
